# Time entries are drafted one day at a time and applied only after review

The drafter never writes time entries straight from activity. It writes a day proposal, the user annotates and approves it, and only then is it applied to Timing. The user then reviews and edits in Timing, and the next daily run starts with reconciliation, feeding any lessons into the playbook. Time entries drive a real invoice, so a human stays in the loop until reconciliation shows the drafts are reliably right; scheduled, unattended runs can be revisited then.
